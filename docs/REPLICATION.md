# Reproducing this benchmark

Generated by `python -m nas4textgen.cli replication`. Do not edit by hand — the
declaration lives in `src/nas4textgen/replication.py`, and a document maintained
separately from the code it describes is a document that will disagree with it.

## What each tier costs and what it proves

The tiers nest: `partial` runs everything `smoke` runs, which runs everything
`verify` runs. Running a wave without the checks that make its output
interpretable is a demonstration rather than a replication.

### `verify`

- **hardware** — any CPU, no GPU, no cloud account
- **wall clock** — under ten minutes
- **cost** — nothing
- **proves** — every table and figure in the paper is recomputed from the published benchmark table and matches. It does not retrain anything, so it verifies the analysis rather than the measurements.

### `smoke`

- **hardware** — one GPU, or a CPU with patience
- **wall clock** — minutes
- **cost** — negligible
- **proves** — the training path runs end to end and writes a manifest with every required field. The perplexities are meaningless at this budget and are not compared.

### `partial`

- **hardware** — one GPU
- **wall clock** — about a day for 150 architectures at 100M tokens
- **cost** — roughly 26 USD at low-priority cloud pricing
- **proves** — one nested wave reproduces. Because the waves nest, wave one is a space-filling sample on its own and supports the surrogate study and an interim front.

### `full`

- **hardware** — a GPU cluster; the campaign used five T4 nodes
- **wall clock** — about twelve days at five concurrent nodes
- **cost** — roughly 174 USD at the measured low-priority price
- **proves** — the whole benchmark. Tolerance-exact against the measured seed ROPE, not bit-exact: GPU kernel scheduling is nondeterministic and the campaign's own re-runs of identical architectures moved perplexity by 0.07 to 0.33 per cent.

## Determinism, per stage

Two classes, and the difference is not a matter of degree. Enumerating the space
is arithmetic and gives the same bytes on any machine. Training a transformer on
a GPU does not give the same bytes twice on the same machine — the campaign's own
re-runs of identical architectures at identical seeds moved perplexity by 0.07 to
0.33 per cent. Publishing both as "reproducible" would be true of one and
misleading about the other.

| stage | tier | reproduces | tolerance |
|---|---|---|---|
| structural gate | `verify` | bit_exact | exactly |
| audit of the prior protocol | `verify` | bit_exact | exactly |
| enumeration and exact cost front | `verify` | bit_exact | exactly |
| sampling designs and execution order | `verify` | bit_exact | exactly |
| corpus retrieval | `verify` | tolerance_exact | the corpora are fetched from upstream repositories that can change |
| tokenisation | `verify` | bit_exact | exactly |
| one training run | `smoke` | tolerance_exact | bit-exact on CPU, where deterministic kernels are enabled and cost nothing |
| one sweep wave | `partial` | tolerance_exact | the same seed ROPE, applied per architecture |
| benchmark table and exact front | `verify` | bit_exact | exactly |
| surrogate study | `verify` | bit_exact | exactly |
| characterisation | `verify` | bit_exact | exactly |
| the remaining waves | `full` | tolerance_exact | the same seed ROPE as one wave, applied per architecture |

## The stages

### structural gate

```
python -m nas4textgen.cli gate
```

- **reads** — the search space definition in code
- **writes** — artifacts/gate/structural_gate.json

Eight checks the space must pass before any sweep is submitted: cardinality, injectivity of the encoding, no inert genes, the reference architecture dominated. Arithmetic on integers, so any machine gives the same file.

### audit of the prior protocol

```
python -m nas4textgen.cli audit
```

- **reads** — the WikiText-2 test split, retrieved on first use
- **writes** — artifacts/audit/prior_protocol.json

Re-derives the figures section 5 rests on: what an empty generation scores under the prior protocol, on which strata, and how far apart four model-free hypotheses are. CPU only and a few seconds. Listed in the verify tier because a reader who can run nothing else should still be able to check the claim the paper makes about someone else's work.

### enumeration and exact cost front

```
python -m nas4textgen.cli enumerate
```

- **reads** — the search space definition in code
- **writes** — artifacts/space/enumeration.csv, artifacts/space/enumeration_summary.json

Closed-form parameter and cache counts for all 1,099 architectures.

### sampling designs and execution order

```
python -m nas4textgen.cli designs
```

- **reads** — artifacts/space/enumeration.csv
- **writes** — artifacts/space/sampling_designs.json

The maximin order the sweep runs in, and the nested waves. Seeded, and the order is recorded rather than recomputed at submission so a later change to this code cannot reorder a campaign already in flight.

### corpus retrieval

```
python -m nas4textgen.cli fetch
```

- **reads** — the corpus registry in code
- **writes** — data/cache/<corpus>/<split>.jsonl, artifacts/corpora/retrieval.json
- **requires** — network access to the dataset hosts

The only stage that reaches the public internet. Everything after reads the cache.

### tokenisation

```
python -m nas4textgen.cli tokenise
```

- **reads** — data/cache/<corpus>/<split>.jsonl
- **writes** — data/cache/<corpus>/<split>.tokens.jsonl
- **requires** — the corpus is cached and its hash matches

Once, rather than once per job. Fixes the token stream so a rebuild that moved the tokeniser cannot change it under half a sweep.

### one training run

```
python -m nas4textgen.train --h 2 --d-head 32 --n 2 --ffn 2 --kv 1 --corpus wikitext103 --token-budget 200000 --allow-cpu --output artifacts/smoke
```

- **reads** — the tokenised cache
- **writes** — artifacts/smoke/manifest.json
- **requires** — the corpus is tokenised; the output directory is writable
- **resumable** — re-running after an interruption continues

Checkpoints every ten minutes or longer, sized so the writing stays under five per cent of runtime. Resuming reproduces the uninterrupted result exactly on CPU.

### one sweep wave

```
python -m nas4textgen.cli sweep --wave 1 --submit
```

- **reads** — the corpus cache in project storage, the published training image
- **writes** — one manifest per architecture in the artifact container
- **requires** — the platform is applied; the corpus is uploaded and verified; the image matches this checkout
- **resumable** — re-running after an interruption continues

Waves nest, so wave one is a space-filling sample on its own — fill distance 0.333 against 0.594 for a uniform random sample of the same size.

### benchmark table and exact front

```
python -m nas4textgen.cli table
```

- **reads** — artifacts/manifests/runs.jsonl
- **writes** — artifacts/benchmark/table.csv, artifacts/benchmark/summary.json
- **requires** — at least one run met its token budget

Refuses rows measured under different precision, corpus vintage, token budget or tokeniser. Given the same manifests it produces the same table, and the manifests are published with it, so the verification tier rebuilds the table rather than taking it on trust. It did take it on trust: the stage still declared that it reads the manifests from the artifact container and so needs an account, which had stopped being true when the command was changed to read the published mirror. Nothing rebuilt the table for as long as that stood, and an assembly bug that moved the measured front from 220 architectures to 218 went unreported.

### surrogate study

```
python -m nas4textgen.cli surrogate
```

- **reads** — artifacts/benchmark/table.csv
- **writes** — artifacts/surrogate/slate_at_<rows>.json, artifacts/surrogate/budget_curve.json
- **requires** — the benchmark table exists

Fourteen candidates on shared folds, every one scored against two trivial predictors and disqualified if it beats neither. Seeded throughout.

### characterisation

```
python -m nas4textgen.cli characterise
```

- **reads** — artifacts/benchmark/table.csv, artifacts/pilot/results.json
- **writes** — artifacts/characterisation/
- **requires** — the benchmark table exists

Depth against width at matched parameter count, the grouped-query frontier, gene effects on measured quality, and whether the two cost fronts differ.

### the remaining waves

```
python -m nas4textgen.cli sweep --wave 5 --submit
```

- **reads** — the corpus cache in project storage, the published training image
- **writes** — one manifest per architecture in the artifact container
- **requires** — one wave has completed, so the throughput model exists; the image matches this checkout
- **resumable** — re-running after an interruption continues

The waves nest, so submitting the last one submits whatever the earlier ones did not cover — re-running it after an interruption skips every architecture already measured rather than paying for it again. Declared as a stage because the full tier quoted a cost and a duration for work no stage named, and a tier with no stages reports success for having done nothing.
